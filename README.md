# 附中影像

网站：[附中影像](https://drivinggodj.github.io/nsfz-campus-gallery/)。源代码：[DrivingGodJ/nsfz-campus-gallery](https://github.com/DrivingGodJ/nsfz-campus-gallery)。

当前公开网站提供校园地图、照片浏览和共享点赞。公网投稿页已发布，原片存储 R2 尚待账户开通，因此暂不接受公网投稿。本地导入与审核体验继续可用。完整投稿配置保留在 `worker/wrangler.jsonc`；这次使用 `npm run likes:deploy:only` 部署点赞，避免未开通的 R2 影响浏览网站。

南师附中察哈尔路校区的 3D 校园照片档案。校园体块由 OpenStreetMap 建筑轮廓生成，照片记录水平位置、镜头朝向、仰俯角和文字描述；普通照片只记录楼层，航拍照片记录拍摄高度。

公开网站是静态文件；管理员编辑和审核在本地运行；同学可通过公开投稿页提交照片。OSM 最初提供 17 个建筑轮廓；根据校友标注拆分、合并并补充后，当前有 18 个地上建筑体块，另有地下羽毛球场与走廊。所有建筑及分区均按楼层数 × 层高计算高度，默认层高为 3.6 m，可在编辑器中调整。建筑资料仅保存名称、楼层数与层高，不设置固定总高度；主教学楼主楼与副楼分别填写楼层数并计算，初始为主楼五层、副楼六层。

已按标注拆分看台与办公室、剧场与实验楼，合并原 IB 教学楼的两个体块，补充体育馆、地下通道入口及通道、天桥。地下入口以地面方块和文字标签表示，地下视图保留沿弧线下降的旋转楼梯连接地下通道，出口保持地下同层连接。天桥主跨沿原 OSM 天桥道路建模，两端楼梯按新标记截短；上口落地后通过平面道路接回原路，体育馆向跑道靠近、保留间距并沿长边延长，支线随模型调整后准确接入二楼，下操场支线在平面上与地下走廊宽边平行；桥面随体育馆的二楼层高调整。地下通道直线与看台、办公室平行，入口旋转楼梯反向弯折后沿同轴线进入通道。操场沿 OSM 方向绘制红色六道跑道、分道线与草地球场。新增轮廓根据截图估算；跑道数量及地下空间深度 3 m 均为示意。地图工具栏的“地下空间”按钮可统一显示或隐藏通道、地下连接点、走廊、风雨跑道及羽毛球场的透视示意；地面入口始终可见。天桥、地下通道、走廊、风雨跑道及羽毛球场的地图标签仅显示名称，不显示尺寸或说明文字。未知建筑尚未确认层数，暂按默认三层显示，可在本地建筑资料中校准。

页面、编辑器和三维校园地图自动跟随系统切换深色／浅色模式，切换即时生效，当前地图视角和未保存的编辑内容会保留。照片保持原色。

默认校园全景从校门外侧看向校园，露出食堂弧形轮廓和宿舍天文台、校徽牌匾；“回到校园全景”恢复同一方向。

地图滚轮、触控板缩放、双指开合、中键拖动和工具栏前进／后退按钮均沿当前视线移动相机及观察中心，可越过原观察中心，前后距离不设边界。靠近地面时步幅减小但不会降为零；拖动旋转与右键平移继续可用，走远后可点击“回到校园全景”。照片展示模式保持保存的固定视角，上传编辑中的拖动只调整照片角度。

选中照片或任意可选地点（建筑、湖泊、操场、树林、各类走廊等）时，平滑移动到画面中心。单指或鼠标左键开始拖动时，以当前画面中心视线与地面的交点作为环绕中心，拖动期间固定该点。交点超出校园边界，或视线不与前方地面相交时，改为保持相机位置的原地转头。选中的对象仍在视野内时，优先围绕该对象旋转；移出视野或取消选择后恢复地面判断，不自动取消选中或筛选。地点只要还有部分进入画面，就仍算可见。按下时不改变画面，下一次拖动重新判断；双指开合和平移仍保留原有操作。

未名湖靠校史馆一侧的岸边新增“诚朴雄伟碑”，按参考照片使用深色不规则石块、低矮石基和金色繁体“誠樸雄偉”文字；碑身沿岸线横放，文字朝湖内，只在正面显示。该地标保留模型，地图不额外显示文字标签，也不作为单独拍摄地点。

## 本地使用

需要 Node.js 22.12 或更高版本。

~~~sh
npm install
npm run dev
~~~

- 浏览预览：<http://127.0.0.1:5178/>
- 本地编辑：<http://127.0.0.1:5178/editor.html>

导入照片后：

1. 航拍照片自动读取原文件的经纬度与高度，并在校园范围内定位。普通照片选择拍摄地点和楼层，不填写高度。地点包括主要建筑、湖、篮球场、操场、标本林及有名称的地下空间和走廊；也可直接点击地图上的名称。
2. 未自动定位的照片点击“标记拍摄位置”，再点击拍摄者所在位置。航拍缺少参数时可补充高度；普通照片在地图中的高度按楼层与所在层面计算，不作为照片资料保存。
3. 调整水平朝向（正北 0°、东 90°、南 180°、西 270°）和仰俯角（向上为正）。
4. 填写标题、描述和日期／时间。原片里的作者与版权会自动读取；没有的留空，编辑器可逐张修改。
5. 点击“体验拍摄视角”，在保存前查看当前草稿的位置、楼层或航拍高度、朝向、仰俯角与焦距；可直接拖动画面调整角度，松手后同步朝向和仰俯角；滑块及楼层、焦距修改即时更新，点击“返回地图”继续定位。
6. 点击“保存到内容库”，再打开“浏览预览”检查，构建并推送仓库。

本地编辑器支持批量导入。失败照片单独报告，成功导入的照片保留。当前照片未保存的字段会暂存到此浏览器，返回条目可继续编辑；已保存条目和导入草稿也保存在电脑上。

浏览目录可按同一套拍摄地点筛选。新记录通过 locationId 关联建筑或校园地点，buildingId 只保留实际建筑关联；旧照片仍兼容原有 buildingId，保留水平位置与楼层；保存或导出时移除普通照片旧的高度字段。宿舍1、宿舍2与宿舍共用一个“宿舍”轮廓、名称及拍摄地点，合并后初始为六层；旧地点编号自动对应新宿舍，照片水平位置和楼层保持不变。篮球区按标注绘制四块并排场地，包含边线、中线、中圈、罚球区、三分线等简化标线，场地配色面互不重叠。

导入时用 [exifr](https://github.com/MikeKovarik/exifr) 从原文件读取拍摄日期／时间、时区（文件提供时）、相机、镜头、焦距、等效 35 mm 焦距、光圈、快门与 ISO，编辑器和照片详情均可查看。缺失字段省略；没有 EXIF 的照片不会使用文件修改时间冒充拍摄日期。拍摄日期和时间可以手动修正，相机记录的原始时间独立保留。无时区的相机时间保持原值，避免跨日偏移。只公开选定参数，不复制序列号或全部原始 EXIF。航拍额外保留经纬度、相对高度与海拔；手机和普通相机照片不保留高度或 GPS 参数。

地图上的小箭头表示照片朝向。选中照片或进行本地标注时，还会显示随朝向与仰俯角转动的半透明视角扇形；照片详情和编辑器显示水平视角数值。优先使用 EXIF 的等效 35 mm 焦距；只有实际焦距时，先按全画幅估算并明确标注，可在“校准镜头视角”中选择画幅倍率。没有焦距时保留朝向箭头，可手动填写等效焦距补出扇形。校准值独立保存到照片的 view 字段，不改写原始 EXIF。

视角采用直线投影镜头的近似公式 `2 × atan(画面宽度 / (2 × 焦距))`，以 35 mm 画幅对角线和输出图片比例换算宽高，竖拍的水平视角相应变窄。计算依据参见 [Edmund Optics 的焦距与视场说明](https://www.edmundoptics.com/knowledge-center/application-notes/imaging/understanding-focal-length-and-field-of-view/)。照片裁切、鱼眼镜头和近距离对焦可能产生偏差，可手动校准等效焦距。扇形长度固定为视觉示意，不代表拍摄距离，也不计算建筑遮挡。

照片详情和大图底部均可点击“进入照片视角”，地图用约 0.85 秒的平滑运动到达拍摄位置，并按镜头方向与焦距对齐；“返回地图”或 Esc 平滑恢复进入前的地图视角。展示已保存照片时，镜头固定为照片保存的朝向和仰俯角。只有本地上传／编辑预览支持鼠标、触屏直接拖动，位置固定，只转动镜头，没有阻尼或角度补间；方向键微调，Shift 加方向键每次调整 5°。编辑预览进入过程中开始拖动会立即交给手动控制；松手后更新浏览器暂存角度，仍需点击保存才写入内容库。取景框保持原照片的横竖比例，窄屏也保留完整镜头范围；无焦距时明确提示采用默认视角。普通照片按楼层及所在层面推算眼高，航拍使用相对起飞点高度；只有海拔或尚未定位的照片需先补齐参数。预览仅使用校园示意模型，不覆盖原照片或自动保存草稿；系统启用减少动态效果时直接切换。手机进入视角后收起目录，返回时恢复目录。

照片原文件保存在忽略的 .local/originals/。对外的下载版本为自动纠正旋转、转换 sRGB、移除原 EXIF 的全尺寸高质量 JPEG，界面明确写作“高清 JPEG”，不标为原文件。生成的缩略图和展示图为 WebP。单张导入上限 40 MB；不支持的 HEIC/RAW 请先导出 JPEG。

照片移出内容库时只移除列表记录，文件保留，可使用“恢复照片”；历史记录在 .local/backups/，移除记录在 .local/removed/。静态构建仅复制内容库当前引用的图片，草稿、移除图片、本地原文件和编辑器都不会进入 dist。

## 静态构建与 GitHub Pages

~~~sh
npm test
npm run build
npm run preview
~~~

静态预览：<http://127.0.0.1:4178/>。dist/ 可以独立上传到静态托管服务，不含在线编辑器或服务端凭证；共享点赞由下面的独立云端接口提供。

将项目推送到 GitHub 的 main 分支后，在仓库 Settings → Pages → Source 选择 GitHub Actions。仓库已提供 pages.yml 自动测试、构建和部署。

项目页面默认网址是 https://用户名.github.io/仓库名/。工作流会自动配置对应路径。如果使用 用户名.github.io 仓库或自定义域名，将工作流的 PAGES_BASE_PATH 改为 /。本地构建默认相对路径，支持放入任意子目录。

GitHub Pages 网站总大小上限 1 GB。本项目在导出时检查图片引用与文件大小，并在图片超过 900 MB 时停止构建，为网站和地图留出余量。图片直接存 Git，避免反复覆盖大文件。日常编辑不会自动提交或推送；推送 `main` 后由 GitHub Actions 自动发布。

## 点赞、目录排序与署名

照片目录支持上传顺序（最新在前）、拍摄时间（最近在前）、点赞最多。缺少拍摄时间的照片排在最后；同赞数或同拍摄时间按上传顺序排序。新照片在导入时记录不可修改的 uploadedAt；旧照片没有准确上传时间时保留内容库的原始排列作为顺序依据，不用拍摄时间冒充上传时间。排序不会修改内容库或地点、楼层、季节筛选。

点赞免登录，用浏览器保存的随机标识识别，每个标识对每张照片只能留一个赞，可以取消。D1 的唯一约束和事务保证重复请求不会重复计数。清除网站存储、无痕模式或换浏览器可能产生新标识，因此不能当作严格的真实人数统计。没有读取 MAC 地址或采集设备指纹。浏览器禁止存储时仍能查看赞数，停止写入点赞。

本地 `npm run dev` 自动使用与云端相同的接口逻辑和本地 D1 数据库，数据放在 `.local/likes-db/`。本地点赞不上传到云端。服务失败时显示提示、允许重试，不显示伪造的成功状态。没有配置云端网址的静态网站显示“点赞服务尚未连接”；其他浏览功能继续可用。

作者读取 EXIF Artist、IPTC Byline、XMP dc:creator；版权读取 EXIF Copyright、IPTC CopyrightNotice、XMP dc:rights。不用相机拥有者字段推断作者，不添加默认版权许可。原始元数据与可编辑署名分别保留。旧照片可以执行 `npm run photos:credits` 从 `.local/originals/` 补全未设置的字段：自动备份、不修改位置与文字、不覆盖手动填写或明确清空的署名。原片缺失或没有相关元数据时留空。

### 接入 GitHub Pages 的共享点赞

前端继续使用现有 GitHub Pages。Worker 位于 `worker/`，只提供点赞接口，没有在线修改照片的权限。需要一个 Cloudflare 账户；数据库和 Worker 部署在明确指定的同一账户。

1. 在 `worker/wrangler.jsonc` 填写目标 `account_id`。执行 `npx wrangler d1 create nsfz-photo-likes --config worker/wrangler.jsonc`，将返回的数据库编号填入 `d1_databases[0].database_id`。
2. `vars.ALLOWED_ORIGINS` 填网站来源，例如 `https://用户名.github.io`，不含仓库路径或末尾斜杠。自定义域名填写实际 HTTPS 来源，多个来源用逗号隔开，不支持通配符。
3. 执行 `npm run likes:migrate` 创建远端表，再执行 `npm run likes:check` 和 `npm run likes:deploy`。部署检查会拒绝空网站来源、占位数据库编号或未指定账户。
4. 在 GitHub 仓库 Settings → Secrets and variables → Actions → Variables 设置 `LIKES_API_URL` 为 `https://nsfz-photo-likes.你的子域名.workers.dev/api/likes`，再运行现有 Pages 工作流。此网址是公开接口地址，不是密钥，不要将 Cloudflare token 放入前端。
5. 增删照片后也执行 `npm run likes:deploy`，让云端的已发布照片名单与网站同步。该操作保留数据库中的已有点赞。`npm run likes:manifest` 仅重建名单，不改照片。没有配置来源时 Worker 默认拒绝访问。

本地生产构建可参考 `.env.production.example`，使用忽略的 `.env.production.local`。`npm run likes:check` 只检查类型和打包，不部署云端、不代表公网验证成功。上传名单生成自当前已保存照片，草稿不会进入云端。请求采用参数化 SQL、每浏览器限频、限定来源、受限请求体和受限查询批量；公共匿名接口的限频不能防止有人不断更换标识刷赞。

## 地图与数据

- data/osm-source.json：下载时的 OSM 原始快照，供核查来源。
- data/campus-corrections.json：根据校友标注保存的拆分、合并轮廓、分区楼层与新增通道；刷新 OSM 时再次应用。主教学楼主体五层，标出的翼楼六层，两部分仍共用一个建筑标识，分界沿现有直线通道拉平；副楼层数保存到 partFloors，修改后与主楼分别计算高度。地下走廊沿看台方向形成三边直角 U 形，在两侧与地下羽毛球场相接，球场旁的横向走廊不存在。两者的右边缘与看台外侧边线对齐。两侧地下走廊之间另有独立的风雨跑道，在同一地下高度连接两侧，以半透明跑道及分道线表示。小卖部旁教学楼后方区域补充“标本林”，以简化树木显示并保留道路和建筑间距。通道出口是地下同层连接点；西侧补充一栋未知建筑。
- public/data/campus.json：简化后的建筑、道路、景观与固定坐标原点。
- public/data/site.json：照片及建筑手动修正，属于需要提交的内容。
- public/media/：内容库照片的缩略图、展示图、下载 JPEG，需要提交。
- .local/：草稿、原始照片、备份；仅保存在本地，勿当作唯一备份。

地图采用 WGS84 经纬度转换为校园范围的米制坐标：X 向东，Z 向南，Y 向上；原点固定在 32.0797155, 118.7515366。模型缩放、旋转仅改变查看视角，不修改照片位置。普通照片的显示高度由楼层 × 层高及所在层面计算。航拍优先采用 DJI XMP 的 RelativeAltitude（相对起飞点，见 [DJI 高度说明](https://developer.dji.com/onboard-sdk/documentation/guides/component-guide-altitude.html)），未提供时保留 AbsoluteAltitude 或带 GPSAltitudeRef 的 EXIF 海拔，并明确显示高度基准。地图尚无地面海拔标定，因此仅有海拔时只定位水平方向，不把海拔当作离地高度。坐标超出地图编辑范围时保留来源坐标并提示手动定位。

~~~sh
npm run map:refresh
~~~

手动刷新从 Overpass 获取校园及附近数据，不在访客浏览或常规构建时请求 OSM。提取失败会保留现有地图；手动建筑修正在 site.json 中按 OSM 编号保存，不被刷新覆盖。地图源更新后应在编辑器核对建筑编号和照片位置。

## 验证范围

自动检查覆盖图片转换、草稿隔离、位置校验、内容版本冲突、软移除恢复、路径约束、EXIF 参数读取、跨日时间保持、日期校验、地图修正重复应用及静态导出；另覆盖视角计算与横竖拍、扇形朝向和仰俯角、校准值保存/导出/恢复、旋转楼梯地下连接、天桥二楼/地面分支、跑道范围和场地包含关系。此前浏览器验证覆盖地图操作、本地导入与保存、楼层与方向标注、详情、大图、下载、参数显示和窄屏布局；本次跑道、楼梯、天桥与视角扇形的浏览器视觉验收因自动审批拦截而未完成。

航拍识别与楼层记录检查覆盖带 EXIF/XMP 的 JPEG 导入、经纬度投影、零高度、海拔正负基准、缺失及范围外信息、普通相机 GPS 不误判、保存/恢复/导出和四种表单/详情状态的离线渲染。


深浅色模式检查覆盖系统偏好初始读取、动态切换及监听清理、深色文字与选中状态对比度。另以当前校园几何离线渲染比对地图配色；系统切换后的浏览器视觉效果仍待实机验收。

照片视角检查覆盖方向与正上/下方拍摄、楼层和桥面高度、横竖画框及窄屏投影、平滑往返与原视角恢复、快速反复切换、未保存参数更新、减少动态效果和缺失定位/海拔提示。另在无需浏览器的 Three/React 场景中验证实际相机及轨道控制的暂停与恢复、上传／编辑预览中的原生鼠标及触屏拖动即时响应、角度暂存回传、拖动后缩放窗口的朝向保持、指针取消和键盘操作，以及照片展示时鼠标／触屏／方向键均不改变镜头，并离线渲染按钮和详情状态；浏览器中的拖动手感、过渡观感和手机布局仍待实机验收。

## 同学投稿与本地审核

网站增加了“投稿照片”入口。公开投稿页是 `submit.html`，仍由 GitHub Pages 提供；动态服务与点赞共用 Cloudflare Worker / D1，原片直接传到私有 R2。没有任何审核密钥写入网页。本地模式可以体验；线上投稿页已发布，待 R2 开通并完成真实直传验证后开放。

### 你怎么审核

1. 在自己的电脑运行 `npm run dev`，打开 [本地编辑器](http://127.0.0.1:5178/editor.html#review)，进入左侧“审核”。第一次上线后，在“审核服务设置”填写投稿服务地址和审核密钥；密钥只保存到本机 `.local/submission-service.json`，不会进入公开构建。此文件权限为仅当前用户读写。
2. 点击“导入原片审核”。原片会在本机解码、校正方向、读取真实元数据，生成一个可编辑草稿；云端文件格式声明不会替代本机验证。上传链接有效期为 5 分钟，未过期时显示倒计时，并暂不开放导入，避免有人用仍有效的链接覆盖正在审核的原片。
3. 在右侧核对标题、作者／版权、地点、楼层和镜头方向。可点“照片与模型同屏”“体验拍摄视角”。点“通过审核并入库”保存；不合适的投稿可填写原因退回。无法解码的投稿也能直接在列表退回。
4. 审核通过会加入 **本地内容库**，尚未自动发布。检查浏览预览，构建、提交并推送项目，GitHub Pages 更新后同学才能在网站上看到。照片数量变更后也要更新点赞服务的照片名单（`npm run likes:deploy`），以允许新照片点赞。若入库成功但云端回复失败，会提示“已入库，状态待同步”；再次通过审核只同步状态，不重复导入。

审核草稿和投稿来源关系都留在 `.local/`。退回的已导入草稿仍可恢复，公开内容不会自动删除。原片、投稿凭证、服务设置、审核密钥以及本地编辑器都不包含在 `dist/` 中。

### 你自己提交的快速通道

直接在编辑器“照片”页批量拖入原片，标注后“保存到内容库”即可，**无需经过公网投稿与审核队列，也不消耗 Cloudflare 投稿额度**。后续发布步骤与现在一致。不要把审核密钥提供给同学；他们使用公开投稿页即可。

### 同学怎么提交

打开 [本地投稿体验](http://127.0.0.1:5178/submit.html) 或上线后的“投稿照片”页，选图、标注、体验镜头方向，点击“提交审核”。网页支持 JPEG / PNG / WebP / AVIF，单张最多 40 MB、7000 万像素。其他格式可交由你用本地编辑器导入。普通照片只填写楼层；航拍自动读取经纬度和高度，缺少时补充。作者和版权只有原片有记录时自动填入，否则留空；同学可修正。普通照片的完整 GPS 和设备序列号不会成为公开资料。

提交成功后保留一份投稿凭证，可以下载保存。通过“我的投稿记录”查询审核结果；清除浏览器数据后也可读取下载的凭证。凭证提供该份投稿状态查询权限，不能浏览其他同学的原片。显示“审核通过，等待网站发布”只表示已加入你的本地内容库，不代表 GitHub Pages 已更新。

### 限额与失败提示

- 单张 40 MB；待审核原片总容量默认最多 **9,000,000,000 字节**（约 9 GB），为免费存储留余量。
- 网站自行限制 **100 次新投稿／UTC 日、1 GB 原片／UTC 日**。新上传会话也计入额度；相同会话重试不重复占名额。凌晨 UTC 00:00，即北京时间 08:00 重置。
- 同一来源 IP 最多 12 次投稿接口请求／分钟；达到时提示稍后重试。同学共享校园出口 IP 时也共享此短期限制，部署后可根据实际使用调整。
- 容量满、投稿日额度满、已识别的 D1 日读写／容量限制、Worker 每日请求额度（1027）、运行时间错误（1102）、上传失败和网络失败都有提示。Cloudflare 有时在请求到达代码前拦截且不返回 CORS 头，浏览器无法确定具体原因；此时明确显示“无法连接，可能是网络或服务限额”，不把网络错误冒充已确认限额。
- 上传失败时保留照片和标注；确认失败可只重试确认。刷新后重新选中同一原片可恢复标注；也可下载标注 JSON 备份。原片本身不会塞进浏览器存储。
- 每小时清理已审核且上传链接已过期的云端原片、过期上传会话及超过 30 天的待审核原片；状态凭证最长保留 90 天。清理删除成功后才释放对应容量，重复清理不会重复扣减。

此上限只能约束本项目的投稿服务；Cloudflare 账户其他应用仍可能消耗共享免费额度。R2 必须配置为私有桶，禁用 r2.dev 与公开域名。可另设 `pending/` 原片 31 天生命周期规则作为清理后备，操作仍以账单／控制台额度为准。

### 正式上线的连接步骤

代码、迁移、类型生成、构建与部署前检查已准备好；D1 与点赞 Worker 已连接正式网站。R2 尚未开通，也未开通收费项。

1. 等项目有 GitHub Pages 网址后，创建或配置 D1 数据库与私有 R2 桶，在 `worker/wrangler.jsonc` 填入 `account_id`、`database_id`、`ALLOWED_ORIGINS`、`R2_ACCOUNT_ID`。`R2_BUCKET_NAME` 必须与 `UPLOADS` 桶一致。`ALLOWED_ORIGINS` 是 `https://账号.github.io` 这种来源地址，不含仓库路径。
2. 创建只允许正式网站主机名的 Turnstile 组件。后端 `TURNSTILE_HOSTNAMES` 精确匹配正式主机名，**不含 localhost**，校验 `photo-submit` action。实际验证必须经过服务端 Siteverify；公开网页的 site key 不属于秘密。
3. 将 `SUBMISSIONS_OWNER_TOKEN`（随机、至少 32 字符）、`TURNSTILE_SECRET`、`R2_ACCESS_KEY_ID`、`R2_SECRET_ACCESS_KEY` 存为 Worker secrets。R2 S3 密钥只授权此桶。不要把密钥提交到仓库或填进 `VITE_` 变量；`worker/.dev.vars.example` 仅有占位值。
4. 用 `worker/r2-cors.example.json` 替换为正式网站来源，配置 R2 浏览器 PUT 的 CORS。签名绑定原片大小和 Content-Type；有效期固定 5 分钟，重试不会延长，链接在过期前可重复使用。需要在真实浏览器验证 R2 PUT、大小限制、过期、CORS 与失败重试。
5. 执行数据库迁移 `npm run likes:migrate`，检查 `npm run submissions:check`，通过配置门槛后 `npm run submissions:deploy`。点赞和投稿同一个 Worker，升级前必须保留已有点赞表。设置定时触发器并验证清理。
6. GitHub 仓库 Actions 变量填写 `LIKES_API_URL`、`SUBMISSIONS_API_URL`（服务的来源地址，**不带 `/api/submissions`**）、`TURNSTILE_SITE_KEY`，重新构建发布。公网投稿未配置时会明确提示“线上投稿尚未开放”，不会假装上传成功。
7. 在本地“审核服务设置”连接线上服务。做一次真实校园网络的投稿 → 审核 → 发布 → 线上回读验收；补测 Turnstile 真实 token / 重放拒绝、R2 直传与超额响应。

本地运行的模拟验证只接受本机请求，不能从网络访问，也不会被编进生产 Worker。生产代码没有跳过 Siteverify 的环境开关。本地数据使用与云端相同的 D1 / R2 接口进行演练；正式服务未连接前，本地投稿仅在当前电脑的审核队列里出现。

# 开发与维护

观众介绍见[项目首页](../README.md)。本文记录本地编辑、照片包审核和发布流程。

## 本地运行

需要 Node.js 22.12 或更高版本。

```sh
npm install
npm run dev
```

- 浏览页：<http://127.0.0.1:5178/>
- 本地编辑器：<http://127.0.0.1:5178/editor.html>
- 投稿页：<http://127.0.0.1:5178/submit.html>

编辑接口只服务于本地。公开构建不包含编辑器、草稿、私有原片和服务端凭证。

## 照片包审核与直接导入

### Mac 审核应用

Apple 芯片 Mac 可以运行 `npm run review:install`，生成并安装“附中影像审核.app”到“应用程序”。应用自带 Node.js 运行组件；打开后自动连接现有项目内容库，不必先开终端或 Codex。需要保留项目文件夹和其中已安装的依赖，现有 GitHub 与 Cloudflare 登录仍保存在本机；应用包不保存或分发账户凭证。移动项目后，可从“文件 → 选择内容库”重新指定位置。

日常操作：

1. 打开“附中影像审核”。点击“导入照片或投稿包”，也可用 ⌘O 或拖入文件。自己的原片可直接批量导入；同学的 ZIP 审核包会保留其中的标注。
2. 逐张核对照片、地点、楼层。点击“照片视角 · 调整角度”后，原照片、模型和参数面板同时显示；可直接修改位置、楼层、航拍高度、朝向、仰俯角、焦距及照片资料，模型实时更新，也可拖动模型对齐镜头。小屏幕的参数面板独立滚动，对照画面保持可见。确认后点击“保存到内容库”；未保存的草稿不公开。
3. 右上角点击“上线”（或 ⇧⌘P），核对新增、更新、移除的数量，点击“提交并上线”。应用会检查内容、提交 GitHub、等待 Pages 发布、核对线上内容，再同步点赞名单并逐批检查所有照片的点赞接口。
4. 出现“上线完成”后，点击“打开网站”。失败时可查看发布记录并重试；照片、原片和提交记录不会自动丢弃。

应用使用独立本地端口 `5188`，原来的网页编辑器仍可使用 `5178`。上线期间冻结内容写入，避免发布一半时发生修改。程序未完成的修改、错误仓库／分支、远端新增内容或登录／网络故障会中止自动发布；不会强制推送，也不自动覆盖其他开发修改。

本地服务随审核应用启动。点击红色关闭按钮只收起窗口，编辑状态和服务继续保留；点击 Dock 图标可回到原窗口。右键 Dock 图标选择“退出”、按 ⌘Q 或从应用菜单退出时，才会结束本地服务及其子进程并释放端口。应用意外退出时也会通知服务关闭。另行启动的 `npm run dev` 由启动它的终端管理，需在该终端停止。

发布检查的临时照片副本会在完成或失败后自动清理，下次上线也会清理历史遗留的临时构建；原片、草稿、内容库和发布日志保留。磁盘空间不足会显示明确提示。网站已发布但点赞同步失败时，会单独说明这一状态并允许重试。名单暂未同步的照片会显示“同步中”，不会使其他照片的点赞一起失效。

第一次打开，macOS 可能询问访问“文稿”或“下载”文件夹，请允许应用读取内容库和投稿包。若误选拒绝，可在“系统设置 → 隐私与安全性 → 文件与文件夹”恢复权限，再点“重试打开”。

### 网页编辑器

1. 从邮件下载投稿 ZIP；投稿收件人为 `drivinggodj@icloud.com`。
2. 本地编辑器进入“照片”，点击“导入照片或投稿包”，或拖入 ZIP。一个 ZIP 可以含多张照片，整体导入后，每张照片会成为独立本地草稿；也兼容旧单张投稿包，不会直接公开。
3. 核对标题、地点、楼层、拍摄时间、镜头方向及署名；使用“照片与模型同屏”和“体验拍摄视角”检查，预览画面可拖动调角度。
4. 接收时点击“保存到内容库”。不接收时不保存，通过邮件回复投稿人。
5. 保存后推送 GitHub，等待 Pages 工作流完成。维护者自己的照片可以直接导入原片并保存，无需生成投稿包或发送邮件。

照片包保留原片，附带每张照片的标注及校验信息。批量包使用 schemaVersion 2，最多 20 张、原片合计 100 MiB；单张上限 40 MiB、7000 万像素。不支持的 HEIC／RAW 请先导出 JPEG。本地导入验证全部照片的 ZIP 结构、体积、SHA-256 和标注范围，拒绝压缩炸弹、路径跳转及不合规数据。投稿包不能指定公开资产路径或照片编号；批量导入失败时，本次已导入草稿退回可恢复的回收记录，避免留下半个待审核批次。

投稿页和 README 显示投稿准则：优先校园景观，尽量避免人物、物品、动物作为主体，禁止同学的大头照、面部特写及侵犯隐私、肖像等权益的内容。投稿人需确认准则后生成照片包；审核时仍需逐张核对内容是否符合准则。

航拍自动读取经纬度与相对起飞点或海拔高度，在校园范围内定位；信息不足时手动补齐。普通照片只记录地点和楼层。地点范围包含主要建筑、场地、湖泊、树林、各类走廊与地下空间；不含小地标。

作者读取 EXIF Artist、IPTC Byline、XMP dc:creator；版权读取 EXIF Copyright、IPTC CopyrightNotice、XMP dc:rights。不用相机拥有者字段推断作者，不添加默认许可。`npm run photos:credits` 从私有原片补全未设置字段，不覆盖手动填写或明确清空的署名，并自动备份。

## 图片与备份

| 文件 | 用途 | 规格 |
| --- | --- | --- |
| `thumbnail.webp` | 地图、目录与合并菜单 | 最长边 420 px |
| `preview.webp` | 投稿与审核预览 | 最长边 1280 px，WebP 质量 65 起 |
| `display.webp` | 观众照片卡片、半透明叠加与沉浸转场的次高清图 | 最长边 2400 px，WebP 质量 88 起，每张小于 500 KB |
| `download.jpg` | 全屏与高清下载 | 全尺寸，JPEG 质量 95 |
| `depth.webp` | 沉浸转场的深度图 | 最长边 768 px，灰度 WebP，质量 90 起，每张不超过 60,000 字节 |
| `.local/originals/` | 私有原文件 | 按原字节保存，不发布 |

预览图和次高清图严格小于 **500,000 字节**。超过上限时先降低质量，必要时缩小边长。高清 JPEG 不套用此限制；它经过旋转纠正、sRGB 转换及 EXIF 移除，不称作原文件。

浏览先显示已加载的缩略图，点击照片立即请求次高清图，卡片与叠加转场复用同一份下载。网站加载点赞数据后预加载前三张；照片在地图可见区域或目录中连续停留约 1.2 秒后，后台逐张预加载少量次高清图。选中照片会取消其他未完成的预加载；后台页面、省流量及极慢网络暂停预加载。沉浸模式在次高清图与深度图就绪后再下载高清，准备好时替换。慢网或加载失败时，已有照片仍可见，旁边保留状态提示。高清只在沉浸模式或下载时请求。

```sh
npm run photos:previews             # 为缺失预览的内容补生成
npm run photos:previews -- --refresh # 按当前规格重建已有预览
npm run photos:limits               # 只调整达到或超过 500 KB 的预览／次高清图
```

这些操作不改高清下载、原片或标注，覆盖前保存旧图到 `.local/backups/`。移出内容库的照片保留文件，可在编辑器恢复；移除记录位于 `.local/removed/`。标注写入有版本冲突检查与历史备份。

### 配套深度图与照片叠加

导入照片后，可在「配套深度图」上传 PNG、JPEG 或 WebP（不超过 10 MB、2000 万像素）。深度图应与照片方向、宽高比例和画面范围一致，近处为黑、远处为白。深度图为可选附件，无附件时使用渐隐过渡。

本地编辑器导入原片或投稿包时会自动补生成缺失深度图，投稿包已提供的深度图会保留并压缩。推理使用本机的 Depth Anything V2 Small 模型，照片不发送到外部服务；生成在独立进程中串行执行，空闲 30 秒后释放模型内存，退出编辑器应用时一并结束。失败时保留照片和标注，可点击「生成深度图」重试，已有图也可以重新生成或手动更换。

生成组件与模型只存放在 `.local/depth-tools/` 和 `.local/models/`，不加入网站发布文件。首次在另一台电脑上配置时运行 `npm run photos:depth-setup`：安装锁定版本的推理组件，下载固定版本模型并校验 SHA-256；已经准备好后可以离线生成。模型来源：[Depth Anything V2 Small ONNX](https://huggingface.co/onnx-community/depth-anything-v2-small)。本机已有组件时无需重新安装。

运行 `npm run photos:depths` 会检查当前内容库和草稿，补齐缺失图，并按当前规格压缩较大的已有图；已经符合规格的图不会重复压缩。报告和操作前资料存放在 `.local/depth-maintenance/`，被替换的旧图保留在 `.local/backups/depths/`。原片、高清下载、拍摄标注和作者版权信息保持原样。

网页投稿生成的 ZIP 会包含每张照片对应的深度图与校验信息。本地审核导入 ZIP 后，深度图随草稿保存；也可在本地编辑器中单独添加、更换或移除。保存到内容库后，静态网站会一并发布深度图。更换或移除前，旧文件自动备份到 `.local/backups/depths/`。

照片下方提供「沉浸看照片」入口，并提示可在沉浸模式下载原图。点击后界面先淡出，再沿深度图显现完整照片；退出时以新的深度前沿逐步显现模型，再淡入恢复界面，边界线跟随网站主题色。沉浸模式底部只保留返回和下载原图，按钮栏以浮动卡片叠在画面上。画布始终占满同一容器，顶部栏和照片卡片的出现、消失不会改变画布尺寸；镜头居中调整也使用动画。进入照片视角后，才会出现「半透明照片叠加」按钮；它直接以 50% 透明度叠上或移除照片，不请求深度图、不播放转场，上传和本地审核时可以边叠加边拖动模型校准。参数固定，不提供调试、渲染、导出或调节面板；观众浏览不需要下载推理模型。

## 校园模型与数据

- `data/osm-source.json`：OSM 原始快照。
- `data/campus-corrections.json`：校园轮廓、分区楼层与设施校准。
- `public/data/campus.json`：当前公开校园地图。
- `public/data/site.json`：已保存照片与建筑资料。
- `src/`：浏览、投稿、本地编辑和三维模型。

`npm run map:refresh` 刷新 OSM 数据并重新应用校准。建筑按楼层数 × 层高计算高度，分区可单独设置楼层。模型用于照片定位展示，建筑高度和部分设施为示意。

## 检查与 GitHub Pages 发布

```sh
npm test
npm run likes:check
npm run build
npm run preview
```

本地默认构建使用相对路径，静态预览为 <http://127.0.0.1:4178/>。推送 `main` 后，GitHub Actions 自动检查、构建并发布 Pages。仓库 Settings → Pages → Source 应为 GitHub Actions。

工作流以 `PAGES_BASE_PATH=/<仓库名>/` 构建。使用根域名部署时改为 `/`。生产环境变量参考 [示例](../.env.production.example)；私有本地配置放在忽略的 `.env.production.local`。

静态导出仅包含已保存且仍被引用的照片；校验路径，在图片总量超过 900 MB 时中止，为其他网站资源留空间。提交成功不代表发布完成，应等待工作流结束，再检查线上网页与图片。

## 共享点赞

主站托管于 GitHub Pages，点赞由 Cloudflare Worker 和 D1 独立提供，接口为 `https://likes.drivinggodj.dpdns.org/api/likes`。浏览器保存随机标识，一张照片只能留一个赞，可取消；换浏览器、无痕模式或清除存储会产生新标识，不是严格人数统计，不读取 MAC 地址。

目录默认按点赞最多排序。同赞数按上传顺序；点赞未读取到时显示提示，暂按上传顺序，加载成功后恢复按赞数排序。上传时间与拍摄时间独立；缺少拍摄时间的照片排在最后。

Worker 配置位于 `worker/wrangler.jsonc`，绑定独立点赞域名；不更改其他服务域名。仓库 Actions Variables 中 `LIKES_API_URL` 指向公开接口，此地址不是密钥。Cloudflare token 不进入前端。

首次接入新的账户时：明确指定 `account_id` 和 D1 数据库 ID，设置 `ALLOWED_ORIGINS` 为网站来源（不含仓库路径，不使用通配符），执行 `npm run likes:migrate` 后检查及部署。已有数据库不需要重建。

```sh
npm run likes:manifest    # 更新已发布照片名单，不部署
npm run likes:check       # 类型与打包检查，不部署
npm run likes:deploy:only # 只部署点赞，不启用旧 R2 投稿服务
```

增删已发布照片后同步名单并部署点赞 Worker，保留已有数据库记录。来源限制、参数化 SQL、唯一约束、事务、浏览器限频与受限查询批量共同保护接口，不能完全防止不断更换标识刷赞。网络或额度异常显示错误并可重试；联网恢复或回到页面时重新读取。国内不同网络的可达性需要实际验证。

公开投稿现在使用浏览器本地 ZIP + 邮件，不依赖 R2、Turnstile 或旧在线投稿队列。仓库保留的旧队列实现不是当前公开投稿入口。
